### Agents (`/agent-dashboard`, `src/pages/AgentsPage.tsx`)
- **Purpose and primary task:** registry of A2A agent cards. Inspect an agent's skills and capabilities, and send it a test message (optionally wrapped in a simulated Home Assistant context block). Also register, refresh and unregister remote agents.
- **Scores:** 20/40. Heuristics at 1 or below: Error prevention 1 (native confirm, a delete icon next to a refresh icon, "undefined" ids, see P0); Help and documentation 1 (no explanation of A2A, card, "Push", "History", or what the simulation block does). Cognitive-load failures: 4/8 (too many same-level choices on a card; unexplained jargon; no progressive disclosure of the HA panel; no clear next step after "No agents registered" because the registry is never empty in practice).
- **Desktop findings (inferred):** two-pane layout, 30% list and detail/chat pane. Page uses a bare `h-[calc(100vh-80px)]` (`:826`) with negative margins, so it breaks if the shell header height changes. The loading and error states replace the whole page including the header and Register button (`:791-818`), so a failed fetch loses navigation context. Title is "Agent Registry" but the nav label is "Agents".
- **Mobile findings:** (observed, 375px) header, count, Refresh and Register Agent fit; cards render without overflow. The URL line under each description was **absent** in the screenshot, consistent with the P0 below. Inferred: list/detail toggles via `hidden md:block` (`:868,895`) with a "Back to agents" text link (`:833-840`, ~20px tall). Icon buttons are `p-1.5` text glyphs (`:199,206`), about 28px, under 44px, and the delete X sits 4px from refresh. Chat input and Send sit at the bottom of an `h-[calc(100vh-80px)]` box; on iOS with the keyboard open `vh` does not shrink, so the input can be covered (inferred).
- **Pain points and friction:**
  1. **P0, live API shape does not match the page (verified by `curl /agents`, rendering partially observed).** The endpoint returns A2A v1.0 cards: no top-level `url`, the endpoint is at `supportedInterfaces[0].url` (for example `/a2a/climate-agent`). `AgentCard.url` (`:40`) is therefore `undefined` for all 10 agents. Consequences traced in source: `key={agent.url}` (`:884`) gives 10 duplicate undefined keys; the URL line (`:193`, `:459`) renders empty; `onSelect` sets `selectedUrl` to `undefined` (`:887`), so `agents.find(a => a.url === selectedUrl)` (`:787`) returns the first agent for any card and `selected` (`:886`) is true for all cards at once; refresh/unregister call `/agents/undefined` (`:83,91`) and the confirm reads `Unregister agent "undefined"?` (`:721`); test messages go to `/agents/proxy?agentUrl=undefined` (`:117`). Fix: normalize on fetch (`url: card.url ?? card.supportedInterfaces?.[0]?.url`) and key by `name`, or check what the register/unregister endpoints actually key on first. `/impeccable harden`.
  2. **P1, unregistering a built-in agent is one click plus a native confirm** (`:203-209`, `:721`). The row cannot tell a user-registered remote agent from the built-in ones; there is no "built-in" marker, so a first-timer can unregister `orchestrator`. Fix: hide or disable delete for built-ins, use `ConfirmDialog` with a consequence line.
  3. **P1, Register dialog is a div modal** (`:612`): no `role=dialog`, no Esc, no focus trap, no focus return, backdrop click does nothing, `autoFocus` only. Input has no label (`:621`); the instruction paragraph is the only description and is not associated (`aria-describedby`). `type="url"` with a failing form-less Enter gives no inline validation. Fix: shared `Modal` on the `ConfirmDialog` `<dialog>` pattern, a real `<label>`.
  4. **P1, color and size carry meaning, not text.** `CapBadge` (`:143-155`) distinguishes enabled from disabled by green vs grey dot and tint; text is identical ("Push", "Streaming", "History"). Disabled and enabled look the same to colorblind users and screen readers. Fix: add `aria-label="Streaming: supported"` or a check/dash glyph; spell "Push notifications" and "State history". `text-[11px]`, `text-[10px]` (`:146,188,226,344`) are below 12px.
  5. **P2, unexplained vocabulary.** "Agent Registry", "A2A-compatible", "agent card", "Push / Streaming / History" and "Simulate Home Assistant" have no help text. A first-timer cannot tell that these are the same agents shown under Definitions, or that this page is a test bench. Fix: one-line page subtitle ("Agents Lucia can route to. Select one to read its skills and send a test message.") and tooltips via visible text.
  6. **P2, simulation panel.** Raw orange classes `orange-500/400` (`:317,327,336,345,353,380,394`) bypass tokens and light theme; the toggle is a hand-built switch (`:321-335`) when `components/ToggleSwitch.tsx` exists; it has no accessible name (the label span is not associated). Field labels `:374` have no `htmlFor`. The emoji `🏠` (`:337`) and `⚠` (`:776`), and glyph icons `↻ ✕` (`:201,208,853`), are text-as-icon with `title` only. "Reset" resets to the current time and defaults without saying so except in `title`. Preview/Template buttons are 10px text toggles with no `aria-pressed`.
  7. **P2, chat area.** No `role="log"`/`aria-live` on messages (`:519-557`); sent text is lost when switching agents? No, history is per agent in state, but it is lost on reload with no hint. Enter-to-send has no IME guard (`:566`). `key={i}` on messages (`:528`). Typing dots use `animate-bounce`, unguarded for reduced motion (`:549`). The Send button disabled style is `bg-amber-glow/40` with `text-on-accent/50` (`:576`): low contrast but acceptable for disabled.
  8. **P2, errors.** Unregister, refresh and register errors go to a toast only (`:700,713,728`); toasts are not `aria-live` (see audit P1.5). A failed test message gets duplicated as a toast and as a chat bubble (`:776-779`). The raw server body is shown (`:77,124`), so users may see JSON or HTML.
  9. **P3, long values.** URL and name use `truncate` with no tooltip on the card (`:187,193`); skill chips are `whitespace-nowrap` (`:226`) in a flex-wrap, fine; skill tag chips can overflow a 375px card if many (`:480`, `shrink-0 whitespace-nowrap` inside wrap, ok). Description clamps at 2 lines with no way to read the rest except selecting the card.
  10. **P3, card is a clickable div** (`:176-183`): no role, tabindex or key handler, so keyboard users cannot select an agent (WCAG 2.1.1). Hover style is `hover:border-stone` which equals the base border (no hover change).
  11. **P3, `refresh` of the whole list reloads with full-page spinner** (`:677,791`): clicking Refresh blanks the page and clears scroll and selection state visually.
- **Bugs and errors:** P0 above. Duplicate React keys (inferred; would log a console warning). `loadAgents` sets `loading` true on every refresh, unmounting `AgentDetailPanel` and losing the typed draft and HA panel state (`:677,791`; the draft `message` lives in the child, so it is reset after any refresh/register/unregister).
- **Performance notes:** (observed) the page stayed on the "Loading agents…" spinner for more than 30s while the browser's connection pool was saturated by SSE streams from other tabs; `curl /agents` returns 11 KB in 40 ms, so the delay was client-side connection starvation, not the endpoint. - **Suggested changes:** normalize the card shape (`harden`); dialog and card semantics (`harden`); badge text and tokens (`colorize`); page subtitle and a "Test bench" heading in the detail pane (`clarify`); header kept visible during load (`polish`); mark built-ins (`clarify`); replace glyph icons with lucide icons already used in `ConversationPage.tsx:2` (`polish`).
- **Not exercised:** all live interaction after the list loaded: card selection, Register dialog, refresh, unregister, sending a message, the HA panel, tablet and desktop widths, light theme, console and network inspection of this page (only the 375px list screenshot and a curl were done). Nothing was clicked that mutates.
