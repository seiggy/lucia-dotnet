## Cross-page observations
- **Secrets are handled three different ways, two of them unsafe:** Providers prefill the real API key (LIVE), Plugin config pulls all secrets unmasked on mount, Configuration masks correctly but its Show secrets toggle wipes unsaved edits. One shared `SecretField` (masked placeholder, replace-on-type, per-field reveal) would fix all three.
- **Dirty/unsaved handling is inconsistent and mostly absent:** none of the three pages guards route navigation or refresh; Configuration guards section changes with native confirm; Providers and Plugins guard nothing; Plugins Discard corrupts sibling state.
- **Save affordance is at the bottom of long forms with no sticky bar on mobile** (Providers `:748`, Configuration `:946`).
- **Three header and card dialects** (Providers/Configuration `font-display text-xl`, Plugins `text-2xl font-bold`; `bg-charcoal` vs `bg-obsidian`), 4px vs 8px vs 12px radii, and a native `confirm()`/`prompt()` mix (`ModelProvidersPage:143`, `ConfigurationPage:44,680`).
- **Destructive actions sit one tap from routine ones** with no consequence copy: Delete provider, Uninstall plugin, Remove repo, Reset All.
- **Tap targets of 24-36px** on list actions and inputs on mobile, versus the 44px toggle and nav drawer, which show the intended standard.
- **Operational note:** the app's startup path shows a bare full-screen "Loading..." with no timeout or failure message when `/api/auth/status` is blocked (LIVE under connection exhaustion, `App.tsx:172-178`); and every page polls `/api/tasks/background` about every 1 to 2s, which together with SSE streams drives the connection-pool starvation seen when several tabs are open.
